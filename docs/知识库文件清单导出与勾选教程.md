# WeKnora 知识库文件清单导出与勾选教程

本文用于从 WeKnora 生产数据库导出当前有效知识记录，生成可筛选、可勾选的 Excel 清单，并在人工确认后安全执行知识库或文件清理。

## 1. 安全边界

1. 导出阶段只允许执行只读查询，不修改数据库、对象存储或向量索引。
2. 清单只包含 `deleted_at IS NULL` 的有效知识记录；已经删除的记录单独进入审计附录，不参与选择。
3. Excel 中未标记的记录一律保留。建议只接受 A 列严格等于 `√` 的行作为待删除项。
4. 批量删除前必须同时核对 Excel、生产数据库和正式 API，三方的知识库 ID、名称、租户和记录数必须一致。
5. 文件级选择只能调用知识删除接口；仅当某知识库的全部有效知识都已被选中，并且用户明确要求删除整库时，才允许调用知识库删除接口。
6. 删除前必须存在一份本轮操作前创建、完整校验且可恢复的备份。删除完成后再创建清理后的新基线；新基线验证通过前不得淘汰删除前备份。
7. 优先调用 WeKnora 正式删除接口。不得直接删除 PostgreSQL 行或对象存储文件来代替业务删除流程。
8. 异步清理未完成前不得开始清理后备份；必须确认数据库、向量、资源目录和实际绑定的对象存储均无有效残留。
9. 文档、脚本、命令输出和操作记录中不得保存密码、访问令牌、API Key 或对象存储凭据。

## 2. 导出生产数据

以下命令需要在已核对 SSH 主机指纹、容器名和数据库名后执行。先在远端 SSH 会话创建权限为 `700` 的随机目录；不要使用固定 `/tmp` 文件名：

```bash
umask 077
EXPORT_DIR=$(mktemp -d /tmp/weknora-export.XXXXXX)
chmod 700 "$EXPORT_DIR"
printf 'EXPORT_DIR=%s\n' "$EXPORT_DIR"
```

后续三个导出命令必须在同一远端会话中执行。

### 2.1 导出知识库汇总

```bash
docker exec -i WeKnora-postgres psql -U postgres -d WeKnora -P pager=off <<'SQL' > "$EXPORT_DIR/weknora-kb-summary.tsv"
COPY (
SELECT
  kb.id AS "知识库 ID",
  kb.name AS "知识库名称",
  kb.tenant_id AS "空间",
  COUNT(k.id) FILTER (WHERE k.deleted_at IS NULL) AS "活跃记录数",
  COALESCE(SUM(k.file_size) FILTER (WHERE k.deleted_at IS NULL), 0) AS "文件总字节",
  MIN(k.created_at) FILTER (WHERE k.deleted_at IS NULL) AS "最早创建",
  MAX(k.created_at) FILTER (WHERE k.deleted_at IS NULL) AS "最近创建"
FROM knowledge_bases kb
LEFT JOIN knowledges k ON k.knowledge_base_id = kb.id
WHERE kb.deleted_at IS NULL
GROUP BY kb.id, kb.name, kb.tenant_id
ORDER BY kb.name
) TO STDOUT WITH (FORMAT CSV, DELIMITER E'\t', HEADER TRUE);
SQL
```

### 2.2 导出全部有效知识记录

```bash
docker exec -i WeKnora-postgres psql -U postgres -d WeKnora -P pager=off <<'SQL' > "$EXPORT_DIR/weknora-active-knowledge.tsv"
COPY (
SELECT
  '' AS "删除（打√）",
  CASE
    WHEN kb.name = '__chat_history__' THEN '系统内部记录，建议保留'
    WHEN kb.name ILIKE '%验收%' OR k.file_name ILIKE '%acceptance%' THEN '验收或测试记录，请核对'
    ELSE ''
  END AS "建议标记",
  k.id AS "知识 ID",
  kb.id AS "知识库 ID",
  kb.name AS "知识库",
  COALESCE(NULLIF(k.file_name, ''), NULLIF(k.title, ''), '（未命名）') AS "文件/知识名称",
  k.file_size AS "大小（字节）",
  pg_size_pretty(k.file_size) AS "可读大小",
  k.type AS "类型",
  k.parse_status AS "解析状态",
  COALESCE(k.folder_path, '') AS "目录",
  COALESCE(u.username, kb.creator_id, '') AS "创建人",
  to_char(k.created_at AT TIME ZONE 'Asia/Shanghai', 'YYYY-MM-DD HH24:MI') AS "创建时间"
FROM knowledges k
JOIN knowledge_bases kb ON kb.id = k.knowledge_base_id AND kb.deleted_at IS NULL
LEFT JOIN users u ON u.id = kb.creator_id
WHERE k.deleted_at IS NULL
ORDER BY kb.name, k.file_size DESC, k.created_at
) TO STDOUT WITH (FORMAT CSV, DELIMITER E'\t', HEADER TRUE);
SQL
```

### 2.3 导出删除审计附录

```bash
docker exec -i WeKnora-postgres psql -U postgres -d WeKnora -P pager=off <<'SQL' > "$EXPORT_DIR/weknora-deleted-audit.tsv"
COPY (
SELECT
  k.id AS "知识 ID",
  kb.id AS "知识库 ID",
  kb.name AS "知识库",
  COALESCE(NULLIF(k.file_name, ''), NULLIF(k.title, ''), '（未命名）') AS "文件/知识名称",
  k.file_size AS "大小（字节）",
  k.parse_status AS "解析状态",
  k.deleted_at AS "知识删除时间",
  kb.deleted_at AS "知识库删除时间"
FROM knowledges k
JOIN knowledge_bases kb ON kb.id = k.knowledge_base_id
WHERE k.deleted_at IS NOT NULL OR kb.deleted_at IS NOT NULL
ORDER BY COALESCE(k.deleted_at, kb.deleted_at) DESC, kb.name, k.id
) TO STDOUT WITH (FORMAT CSV, DELIMITER E'\t', HEADER TRUE);
SQL
```

三个 TSV 全部生成后，另存与主清单完全相同过滤条件的逻辑记录数。TSV 字段可能包含换行，不能用 `wc -l` 代替 SQL 记录数：

```bash
docker exec WeKnora-postgres psql -U postgres -d WeKnora -Atc "
SELECT COUNT(*)
FROM knowledges k
JOIN knowledge_bases kb ON kb.id = k.knowledge_base_id
WHERE k.deleted_at IS NULL AND kb.deleted_at IS NULL;
" > "$EXPORT_DIR/weknora-active-count.txt"

test "$(tr -d '[:space:]' < "$EXPORT_DIR/weknora-active-count.txt")" -ge 0
(cd "$EXPORT_DIR" && sha256sum *.tsv weknora-active-count.txt > SHA256SUMS)
chmod 600 "$EXPORT_DIR"/*
```

主清单记录数以 `weknora-active-count.txt` 为准。Excel 导入后还要使用 `officecli` 读取工作表数据行数，与该值再次比对。

在本机创建私有目录，并通过已核对主机指纹的 SSH 连接下载三个 TSV。传输成功后立即删除远端随机目录：

```bash
SOURCE_DIR="$HOME/Downloads/weknora-export-$(date +%Y%m%d-%H%M%S)"
REMOTE_EXPORT_DIR='<实际 EXPORT_DIR>'
install -d -m 700 "$SOURCE_DIR"
scp "fox@100.78.64.62:$REMOTE_EXPORT_DIR/*" "$SOURCE_DIR/"
(cd "$SOURCE_DIR" && shasum -a 256 -c SHA256SUMS)
test "$(find "$SOURCE_DIR" -maxdepth 1 -type f | wc -l | tr -d ' ')" -eq 5
printf '%s\n' "$REMOTE_EXPORT_DIR" | ssh fox@100.78.64.62 '
  IFS= read -r export_dir
  case "$export_dir" in
    /tmp/weknora-export.*) rm -rf -- "$export_dir" ;;
    *) exit 1 ;;
  esac
'
```

不要使用 `StrictHostKeyChecking=no`，也不要在命令中写入 SSH 密码。

## 3. 使用 officecli 生成 Excel

先加载 Excel 规范并按安装版本查看帮助，不能猜测属性名：

```bash
officecli load_skill excel
officecli help xlsx validation
officecli help xlsx conditionalformatting
```

创建工作簿并导入 TSV：

```bash
FILE="$HOME/Downloads/WeKnora-知识库文件保留选择清单-$(date +%Y%m%d).xlsx"

OFFICECLI_NO_AUTO_RESIDENT=1 officecli create "$FILE"
OFFICECLI_NO_AUTO_RESIDENT=1 officecli set "$FILE" /Sheet1 --prop name=文件选择
OFFICECLI_NO_AUTO_RESIDENT=1 officecli import "$FILE" /文件选择 \
  --file "$SOURCE_DIR/weknora-active-knowledge.tsv" --format tsv --header

OFFICECLI_NO_AUTO_RESIDENT=1 officecli add "$FILE" / --type sheet --prop name=知识库汇总
OFFICECLI_NO_AUTO_RESIDENT=1 officecli import "$FILE" /知识库汇总 \
  --file "$SOURCE_DIR/weknora-kb-summary.tsv" --format tsv --header

OFFICECLI_NO_AUTO_RESIDENT=1 officecli add "$FILE" / --type sheet --prop name=删除审计
OFFICECLI_NO_AUTO_RESIDENT=1 officecli import "$FILE" /删除审计 \
  --file "$SOURCE_DIR/weknora-deleted-audit.tsv" --format tsv --header

DATA_ROWS=$(tr -d '[:space:]' < "$SOURCE_DIR/weknora-active-count.txt")
test "$DATA_ROWS" -ge 0
LAST_ROW=$(( DATA_ROWS + 1 ))
```

当 `DATA_ROWS=0` 时，保留空清单并跳过第 4 节的验证、条件格式和筛选范围命令。

上述 SQL 已生成中文表头。`文件选择` 的列顺序如下：

| 列 | 字段 | 说明 |
|---|---|---|
| A | 删除（打√） | 仅此列决定是否删除 |
| B | 建议标记 | 系统记录、测试或验收提示 |
| C | 知识 ID | 删除前的唯一核对键 |
| D | 知识库 ID | 整库删除的唯一核对键 |
| E | 知识库 | 用户可读名称 |
| F | 文件/知识名称 | 文件名或知识标题 |
| G | 大小（字节） | 精确空间计算 |
| H | 可读大小 | 便于人工浏览 |
| I | 类型 | PDF、DOCX、manual 等 |
| J | 解析状态 | completed、cancelled 等 |
| K | 目录 | 知识库内目录 |
| L | 创建人 | 知识库创建人 |
| M | 创建时间 | Asia/Shanghai 时间 |

## 4. 添加勾选、筛选和提示

表头在第 1 行，`LAST_ROW` 由导出行数计算：

```bash
OFFICECLI_NO_AUTO_RESIDENT=1 officecli add "$FILE" /文件选择 \
  --type validation \
  --prop sqref=A2:A$LAST_ROW \
  --prop type=list \
  --prop formula1=√ \
  --prop allowBlank=true \
  --prop inCellDropdown=true \
  --prop showInput=true \
  --prop promptTitle=删除确认 \
  --prop 'prompt=只在确认删除时选择“√”，留空表示保留。' \
  --prop showError=true \
  --prop errorTitle=无效选择 \
  --prop 'error=请从下拉框选择“√”，或清空该单元格。'
```

给待删除行增加浅红提示：

```bash
OFFICECLI_NO_AUTO_RESIDENT=1 officecli add "$FILE" /文件选择 \
  --type conditionalformatting \
  --prop type=formula \
  --prop ref=A2:M$LAST_ROW \
  --prop 'formula=$A2="√"' \
  --prop fill=FCE4D6
```

设置冻结表头和自动筛选：

```bash
OFFICECLI_NO_AUTO_RESIDENT=1 officecli set "$FILE" /文件选择 \
  --prop freeze=A2 \
  --prop autoFilter=A1:M$LAST_ROW
```

## 5. Excel 交付前验收

```bash
officecli view "$FILE" outline
officecli view "$FILE" issues
officecli validate "$FILE"
officecli view "$FILE" html
```

必须满足：

- `文件选择` 数据行数与生产有效知识数量一致。
- C 列知识 ID 的数量、内容和顺序与导出 TSV 完全一致。
- A 列验证范围覆盖全部数据行，不包含表头或多余空行。
- 没有 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`、`#N/A`。
- HTML 预览中没有 `###`、占位符或被截断的标题。
- 未勾选时，待删除数量为 0，默认保留数量等于数据行数。

## 6. 读取人工选择

推荐只识别严格的 `√`：

```bash
officecli query "$FILE" '文件选择!A[value="√"]' --json
```

如果用户输入了 `删`、`删除` 等其他文字，应先列出原值并让操作者确认，然后统一规范为 `√`；不得静默把任意非空值解释为删除。

从勾选行读取知识 ID、知识库 ID、名称和大小后，应生成删除前汇总：

- 待删除知识数量。
- 涉及知识库数量和名称。
- 每个知识库的有效记录数。
- 文件精确总字节数。
- 是否包含 `__chat_history__` 或其他系统内部知识库。

## 7. 删除前后三方核验

### 7.1 删除前恢复点

执行任何 DELETE 前，必须创建并验证删除前完整备份，至少满足：

- `git bundle verify` 通过。
- PostgreSQL dump 可通过 `pg_restore --list` 读取。
- Docker 镜像和全部卷归档可解压、可列目录。
- 所有实际存储后端的对象清单、资源清单和校验信息已生成。
- 恢复命令、备份路径、Git 提交、schema 版本和镜像 ID 已记录。

删除前必须先按目标资源的 `storage_backend_id` 汇总真实后端。不能因为默认配置是 MinIO，就忽略绑定到 COS、S3、TOS、OSS、KS3、OBS 或 local 的对象：

1. MinIO 和 local：归档对应 Docker 卷或宿主机目录，并校验压缩包可读。
2. COS、S3、TOS、OSS、KS3、OBS：使用该提供商官方 CLI，把目标对象复制到受保护的备份桶或下载到发布备份目录。
3. 保存源后端 ID、provider、bucket、object key、size、ETag/版本 ID；可以取得整文件 SHA256 时同时保存。
4. 备份对象数和精确总字节必须与删除前资源快照一致；随机抽取至少一个对象执行可读性校验。
5. 只有所有实际后端都完成可恢复验证，删除前恢复点才算通过。

如果业务明确接受较早备份的 RPO，也必须在删除前书面记录该边界，不能把“存在一个旧目录”等同于“本轮可恢复”。

### 7.2 文件级删除与整库删除

只删除 Excel 中勾选的文件时，按知识库分组调用记录级接口，单批最多 200 个知识 ID：

```http
POST /api/v1/knowledge/batch-delete
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "kb_id": "<knowledge_base_id>",
  "ids": ["<knowledge_id_1>", "<knowledge_id_2>"]
}
```

只有同时满足以下条件，才允许执行整库删除：

1. 用户明确要求删除整个知识库。
2. Excel 中该知识库已选知识 ID 集合，与数据库中该知识库全部有效知识 ID 集合完全相等。
3. 两个集合排序后逐项一致，不只是数量相等。
4. 知识库 ID、名称、租户和文件总字节已再次展示给用户确认。

整库删除接口为：

```http
DELETE /api/v1/knowledge-bases/<knowledge_base_id>
Authorization: Bearer <access_token>
```

访问令牌只能从安全会话或密钥存储读取，不得写入命令、脚本或操作报告。

### 7.3 删除前核验

删除前分别执行：

1. Excel：确认所有勾选行都属于用户指定范围。
2. PostgreSQL：确认知识库 ID、名称、租户、有效知识 ID 集合和文件总字节。
3. API：逐个 `GET /api/v1/knowledge-bases/{id}`，确认正式接口看到的名称和数量一致。
4. 存储快照：保存 `storage_backend_id`、资源 `provider/physical_path` 和全部 `resource://` 句柄。
5. 向量快照：保存 `vector_store_id` 和实际引擎类型，不能只假设是 PostgreSQL。

### 7.4 删除后核验

删除后等待异步任务结束，再验证：

- `knowledge_bases.deleted_at` 已设置。
- 目标知识库有效知识数为 0。
- 目标知识库有效 chunk 数为 0。
- 资源目录中目标 `resource://` 句柄均为 deleted。
- 有效文件夹、共享、数据源和未完成上传会话均为 0。
- completed 上传会话可作为审计记录保留，但不得再引用临时对象。

向量和物理文件必须按删除前快照中的真实绑定逐项验收：

- `RETRIEVE_DRIVER=postgres`：检查 PostgreSQL `embeddings`。
- Qdrant、Milvus、OpenSearch 或其他向量引擎：按 `vector_store_id` 对应的实际集合、分区或索引过滤知识库/知识 ID。
- MinIO、COS、S3、TOS、OSS、KS3、OBS、local：按每条资源记录的 `storage_backend_id/provider/physical_path` 到对应实例检查对象，不得只检查默认 MinIO。
- 每个目标资源都要验证“资源状态 deleted”和“实际对象不存在”，二者缺一不可。

若正式接口出现“数据库已删除但对象存储未清理”的情况，必须立即停止备份，保留操作清单和日志，确认资源没有被其他有效知识引用后再做受控修复。不能把残留对象直接写入新的基线备份。

## 8. 清理后的备份

删除前恢复点始终保留。只有删除验收全部通过后，才能创建清理后的新基线备份。新备份至少包含：

- 当前 Git 提交及 `git bundle`。
- `.env`、Compose、override 和 `config/`。
- 全部 `com.docker.compose.project=weknora` 运行镜像及镜像清单；不得混入宿主机上的其他项目镜像。
- PostgreSQL 自定义格式 dump 和 schema 状态。
- 全部 WeKnora Docker 卷，尤其 PostgreSQL 和 MinIO。
- MinerU systemd 配置、版本和环境清单。
- 删除操作清单、对象清单、SHA256 和恢复命令。

新备份必须完成 SHA256、`pg_restore --list`、Docker archive manifest、压缩包可读性和恢复脚本静态检查。只有新备份全部通过，才能删除被替换的删除前备份。

## 9. 本轮操作约定

本轮清单的默认策略是“未标记即保留”。实际删除范围由用户明确指定：普通勾选按知识 ID 执行文件级删除；只有用户明确点名整库，并且该库选中集合与全部有效知识集合完全相等时，才执行整库删除。任何额外行、未知标记、集合差异或后端残留都会终止流程并重新核对。
